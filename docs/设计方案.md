### 1.2 关键架构决策与权衡

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| 运行形态 | 静态 H5（`file://` 双击运行） | 零构建、零依赖、零服务器；与小程序页面模型同构，迁移成本低 | 无法联网实时取数，数据需构建期预置 |
| 框架 | 无框架（原生 ES5 IIFE 模块） | 12 个 JS 文件均在 1,200 行内；引入框架的收益低于其带来的构建/体积负担；且小程序原生开发同样无 DOM 框架 | 需手写渲染与事件委托（约 1,149 行视图层） |
| 图表 | 手写 SVG | 无外部 CDN 依赖，离线可运行，配色完全可控（红涨绿跌） | 仅覆盖 4 类图表，无交互缩放 |
| 数据更新 | 构建期快照 | 保证每次回放完全一致、可复现、可写进文档 | 需定期重跑抓取脚本 |
| 时钟 | 离散 tick 驱动（24 tick/日） | 可暂停、可变速、可单步，与"回测式训练"目标一致 | 非实时行情 |
| 持久化 | localStorage 单一状态树 | 与小程序 `wx.setStorageSync` 一一对应 | 单设备，无云端同步 |

**风险特征全部由真实行情回归计算**，无任何估算或编造：

- β：个股日收益率对沪深300 日收益率的最小二乘回归斜率
- 年化波动率：日收益标准差 × √244
- 夏普比率：(年化收益 − 0) / 年化波动
- 最大回撤：收盘价序列的峰谷最大跌幅

| 工商银行 | 0.05 | 20.15% | −16.75% | +110.59% |
| 贵州茅台 | 0.58 | 24.23% | −29.23% | −16.19% |

### 4.2 日内路径生成（核心模拟逻辑）

日线 OHLC 100% 真实；日内走势由确定性算法生成，满足四条硬约束：

1. **起点 = 真实开盘价**，**终点 = 真实收盘价**（严格相等，误差 0）
2. 路径全程 **不越界** 于真实最高价 / 最低价
3. **可复现**：同一（股票代码, 交易日）组合，任意时刻重算得到完全相同的路径
4. **无 `Math.random()`**：全系统禁用真随机，改用 FNV-1a 哈希 + mulberry32 PRNG，种子 = `"600519#137"`

算法流程：

```
锚点序列: [0, open] → [p₁, high|low] → [p₂, low|high] → [T−1, close]
  其中 p₁、p₂ 由 PRNG 在区间内取样；high/low 的先后顺序由当日涨跌方向决定
插值:     相邻锚点间用 smoothstep(3t²−2t³) 平滑过渡
噪声:     幅度 ∝ sin(π·段内相对位置)，锚点处严格为 0、段中部最大
收尾:     对全序列 clamp 到 [low, high]
分辨率:   TICKS_PER_DAY = 24（对应 09:30–11:30 + 13:00–15:00，每 10 分钟一档）
```

这一设计的意义：用户看到的每一根分时线都来自真实历史日的真实开高低收，因此"今天追高被套"或"恐慌割在地板"的体验与真实交易心理高度一致；同时路径可复现，使周报、存档、多设备续玩完全一致。

### 4.3 A 股交易规则建模

| 规则 | 实现 |
|---|---|
| **T+1** | 买入股份进入 `lots`，当日 `avail = 0`；日终结算时 `avail = qty` 解锁 |
| **整手交易** | 买入必须为 100 股整数倍；卖出零股仅允许"全部卖出" |
| **涨跌停** | 主板 ±10%，创业板（300/301）与科创板（688）±20%；涨停不可买入、跌停不可卖出 |
| **停牌 / 未上市** | `suspendedDays` 内与 `listedFrom` 之前禁止交易 |
| **佣金** | 0.025%，双向，单笔最低 5 元 |
| **印花税** | 0.05%，卖出单边 |
| **过户费** | 0.001%，双向 |
| **成本法** | 移动加权平均，买入成本含买入费用 |

> **说明**：以上费率为当前市场主流费率区间的代表值，非任何特定券商的报价。印花税 0.05% 为 2023-08-28 减半后的卖出单边税率。**待核实**：费率政策可能调整，实际以交易所与税务机关最新规定为准。

整手约束的真实后果已在测试中显式验证：**10 万元本金无法买入 1 手贵州茅台**（1,551 元/股 × 100 股 = 15.5 万元）。这不是 bug，而是真实约束——它恰恰是"资金规模决定可选标的范围"这一课程内容的现实依据。UI 在买入面板实时显示"1 手（100 股）需"金额，并在资金不足时给出明确提示。

### 4.4 日终结算

每个交易日收盘执行：

1. T+1 解锁：`p.avail = p.qty`
2. 按真实收盘价估值，写入 `equityHistory`（含账户归一化净值与基准归一化净值）
3. 更新 `peakEquity` 与 `maxDrawdown`

**结算时点曾出现一个真实缺陷并已修复**：原实现先推进 `dayIdx` 再结算，导致快照记录的是次日开盘价、周报归因全为 0。现改为 `Market.step(onDayEnd)` 回调式——**先以当日收盘价结算，再进入次日**。

### 5.2 收益归因口径（可加总、可对账）

采用 Brinson 式框架，四项严格加总等于实际周收益率：

```
R_周 = 市场β + 选股α + 交易择时 + 残差

市场β   = W₀ × R_bench                      W₀ = 期初股票仓位权重
选股α   = Σᵢ wᵢ₀ × (rᵢ − R_bench)            wᵢ₀ = 期初个股权重，rᵢ = 个股周收益
交易    = Σ买 wᵦ×(P末/P买 − 1) − Σ卖 wₛ×(P末/P卖 − 1) − 费用率
残差    = 实际周收益率 − (市场β + 选股α + 交易)
```

- **市场β**：被动承担的市场系统性风险带来的收益，用户无法控制
- **选股α**：选了什么股票带来的超额，衡量选股能力
- **交易**：买卖时点带来的损益（含费用），衡量择时能力
- **残差**：数值残差，用于校验归因精度；测试要求 **|残差| < 0.5 个百分点**

这套口径直接回应用户需求中的"盈亏数据及对应原因分析（市场波动、选股策略、买卖时机等）"——三项主效应与三类原因一一对应，且能量化到具体数字。

测试验证：归因加总 = 实际周收益率（误差 < 0.5pp），残差 < 0.5pp。

### 5.3 行为诊断规则引擎（14 条）

每条规则输出 `evidence`（含具体数字的证据）、`impact`（影响）、`action`（改进动作），并按 high / mid / low 三级定级。

| ID | 规则 | 触发逻辑（要点） | 级别 |
|---|---|---|---|
| R01 | 追高买入 | 在个股近 20 日高位区（分位 > 80%）建仓 | 动态 |
| R02 | 恐慌杀跌 | 在个股近 20 日低位区（分位 < 20%）卖出 | 动态 |
| R03 | 过度交易 | 周换手率显著高于组合规模合理区间 | 动态 |
| R04 | 持仓周期过短 | 平均持有天数 < 3 日且交易 ≥ 3 笔 | mid |
| R05 | 处置效应 | 盈利单平均持有天数显著短于亏损单（截断利润、让亏损奔跑） | high |
| R06 | 缺乏止损纪律 | 存在亏损超过 10% 且当周未处理的持仓 | high |
| R07 | 单一标的仓位过重 | 单一标的权重 > 40% | 动态 |
| R08 | 极端仓位 | 现金比例 > 70%（踏空）或 股票仓位 > 95%（缺乏机动性） | mid |
| R09 | 向亏损仓位加仓 | 对已亏损标的继续买入（向下摊平） | mid |
| R10 | 同一标的周内反复进出 | 同一代码周内既有买又有卖 | low |
| R11 | 交易费用显著侵蚀收益 | 周费用 / 周收益绝对值超过阈值 | mid |
| R12 | 行业暴露过度集中 | 单一行业权重 > 50% | mid |
| R13 | 空仓错过市场上涨 | 空仓且基准当周上涨 | low |
| R14 | 过早兑现盈利 | 卖出于涨幅 > 15% 的标的后该标的继续上涨 | low |

这些规则对应行为金融学的经典结论（处置效应、过度交易、追涨杀跌等），使"经验教训"不是空泛说教，而是**基于用户自己那一周真实操作数据的量化诊断**。

### 5.4 经验教训与行动建议

`buildLessons()` 由数据驱动生成，优先级：

1. **收益来源结构**：本周收益主要来自市场β还是选股α？β 主导 → 提示"收益来自大盘而非选股能力"
2. **交易动作有效性**：交易项为正还是为负？为负 → 量化"本周的买卖操作净损耗 X 个百分点"
3. **个股层面证据**：最大贡献股与最大拖累股各是哪只？权重与涨幅分别是多少？
4. **成本意识**：累计费用占初始本金的比例
5. **相对基准**：超额收益为正/负，以及连续跑赢/跑输的周数

`buildActions()` 输出最多 3 条 P0 / P1 / P2 优先级的下周行动建议，直接引用本周的具体数字（如"将 R07 涉及的单一标的权重从 62% 降至 40% 以内"）。

## 6. 段位评级规则

### 6.1 段位体系

| 大段 | 名称 | 小段 | 每小段星数 | 满星数 |
|---|---|---|---|---:|
| 1 | 倔强青铜 🥉 | Ⅲ → Ⅱ → Ⅰ | 3 | 9 |
| 2 | 秩序白银 🥈 | Ⅲ → Ⅱ → Ⅰ | 3 | 9 |
| 3 | 荣耀黄金 🥇 | Ⅳ → Ⅲ → Ⅱ → Ⅰ | 4 | 16 |
| 4 | 尊贵铂金 💠 | Ⅳ → Ⅲ → Ⅱ → Ⅰ | 4 | 16 |
| 5 | 永恒钻石 💎 | Ⅴ → Ⅳ → Ⅲ → Ⅱ → Ⅰ | 5 | 25 |
| 6 | 至尊星耀 ✨ | Ⅴ → Ⅳ → Ⅲ → Ⅱ → Ⅰ | 5 | 25 |
| 7 | 最强王者 👑 | 累计星制 | — | — |

王者段内称号：**0 星最强王者 → 10 星无双王者 → 25 星荣耀王者 → 50 星传奇王者**。

初始段位：倔强青铜 Ⅲ 0 星。

### 6.2 周结算星数判定

| 条件 | 星数变化 |
|---|---|
| 本周跑赢沪深300（超额 > 0） | **胜利** +1 星 |
| 跑输基准 | **失败** −1 星 |
| 胜利 且 本周综合表现分 ≥ 70（MVP） | 额外 **+1 星** |
| 连续 3 次及以上胜利 | 额外 **+1 星**（连胜奖励） |
| 青铜 Ⅲ 0 星时失败 | **不掉星**（新手地板保护） |
| 失败 且 勇者积分 ≥ 60 | **消耗 60 分保星**，不掉星 |

勇者积分：每次失败累积（上限 120），用于抵扣掉星。

边界处理：星数满 → 进位到上一小段；小段已满 → 进位到上一段 Ⅰ 级 0 星；王者 0 星失败 → 回落至星耀 Ⅰ 满星。

### 6.3 综合表现分（四维加权）

```
表现分 = 0.35 × 收益分 + 0.25 × 风险分 + 0.30 × 纪律分 + 0.10 × 学习分
```

| 维度 | 权重 | 计算方式 |
|---|---:|---|
| **收益分** | 35% | 本周超额收益（相对沪深300）的分段线性映射 |
| **风险分** | 25% | `0.65 × 回撤分 + 0.35 × 集中度分`；回撤与集中度均为"越小越好"型指标，用负值表项插值 |
| **纪律分** | 30% | 100 分起扣：每条 high 级违规 −25、mid −12、low −5（扣至 0 为止） |
| **学习分** | 10% | 本周完成课程数映射（≥ 2 门满分） |

> **设计意图**：收益只占 35%，风险与纪律合计占 55%。这意味着**靠运气重仓押中一只票无法上分**——这直接服务于用户"帮助用户逐步提升选股能力和投资素养"的目标，而非单纯激励冒险。

**风险分插值表**（分段线性，表项 x 取负以复用"越大越好"插值函数）：

| 最大回撤 | 得分 | | 最大单一持仓权重 | 得分 |
|---:|---:|---|---:|---:|
| 0.5% | 100 | | 20% | 100 |
| 1% | 95 | | 30% | 92 |
| 2% | 85 | | 40% | 80 |
| 3% | 76 | | 50% | 65 |
| 5% | 62 | | 60% | 50 |
| 8% | 45 | | 80% | 30 |
| 12% | 25 | | 100% | 15 |
| 20% | 8 | | | |
| ≥200% | 0 | | | |

> 实现中曾出现该表方向反转的严重缺陷（回撤越大得分反而越高），已修复，并新增断言 `回撤/集中度越大，风险分越低` 防止回归。

### 7.1 课程库（16 门，三级分层）

| 层级 | 课程 |
|---|---|

### 7.2 个性化推荐逻辑

```
排序权重：
  1. 课程 relatedRules 命中本周诊断出的违规行为      → 权重最高

取 Top N（默认 3）作为"本周推荐课程"
```

## 9. 测试与质量保障

| 测试套件 | 环境 | 项数 | 覆盖 |
|---|---|---:|---|
| `tools/smoke_test.js` | Node（无 DOM） | **40** | 行情回放可复现性、锚点严格性（起点=真实开盘、终点=真实收盘、不越界于真实高低价）、整手约束、T+1、费用模型、归因对账（加总误差 < 0.5pp、残差 < 0.5pp）、段位升降 11 项、200 交易日随机交易压力测试、存档一致性 |
| `tools/render_test.js` | jsdom（本地文件） | **54** | 加载真实 `index.html`，验证初始渲染、行情搜索与筛选、个股详情弹层、完整买卖流程（含 T+1 锁定）、周报生成与详情、学院与课程作答打卡、时钟推进、读档一致性、控制台无异常 |
| `tools/verify_http.js` | jsdom + 真实 HTTP | **29** | 经 HTTP 抓取 `index.html` 并解析真实 `<script src>` 顺序，验证资源可达性、加载顺序、模块挂载、首屏渲染、交互冒烟、localStorage 写入、控制台无异常 |
| **合计** | | **123** | **全部通过，0 失败** |

> **关于 jsdom 的一个已知坑（供后续维护参考）**：jsdom 30 的内置资源加载（`resources:'usable'`）在并发请求同一服务器时会**随机**报 `Could not load script`，且失败的文件每次都不同；jsdom 30 已移除旧版 `ResourceLoader` 扩展点，新的 `requestInterceptor` 经实测未被 `fromURL` 调用。这是 jsdom 网络栈的局限——同一批 URL 用 curl 逐一下载全部 200 且字节数正确，真实浏览器不受影响。因此 `verify_http.js` 改为自行用 Node `fetch` 下载后按真实顺序注入，既验证了 HTTP 链路又规避了该缺陷。

关键正确性验证：

- **行情真实性**：路径起点严格等于真实开盘价、终点严格等于真实收盘价、全程不越界于真实最高/最低价
- **行情可复现性**：同一（标的, 交易日）重复生成，路径逐点相同
- **归因数学一致性**：四项加总 = 实际周收益率，残差 < 0.5pp
- **长周期健壮性**：200 交易日随机交易，现金不为负、总资产为正、持仓市值与估值一致、周报数量精确 = 40

### 已修复的典型缺陷（供后续维护参考）

| 缺陷 | 性质 |
|---|---|
| 风险分插值表方向反转（回撤越大得分越高） | 严重逻辑错误 |
| 日终快照记录次日开盘价（归因全为 0） | 结算时点错误 |
| `maxBuyQty` 二分死循环 | 进程挂死 |
| 段位结算字段被同名字符串覆盖 | 显示 `undefined` |
| 弹层关闭守卫逻辑写反 | 交互失效 |
| 输入框持有焦点时页面不刷新 | 交互失效 |
| T+1 锁定持仓被误显示为空仓 | 表述错误 |

## 12. 已知限制与待核实项

1. **数据源**：东方财富为第三方公开接口，非官方授权；若商业发行需替换为持牌行情服务商。**待核实**：接口的长期可用性与使用条款。
2. **费率**：佣金 0.025%（最低 5 元）、印花税 0.05%（卖出单边）、过户费 0.001% 为当前主流区间的代表值，**待核实**：具体券商费率与政策变动。
3. **日内路径**：日内走势为算法生成，非真实分时数据。它严格锚定真实的开/高/低/收四点并可复现，但**不等于**历史上真实发生的分时走势。
4. **未建模项**：集合竞价、大宗交易、分红送转除权（已用前复权处理价格，但未模拟现金分红到账）、新股申购、停复牌事件的盘中触发。
5. **回放区间固定**：2024-01-02 ~ 2026-09-01 共 646 个交易日；走完 646 日后需重新开局或更新数据。
6. **教学内容的性质**：课程内容为投资学与行为金融学的通用共识与 A 股交易规则，**不构成任何投资建议**，也不含任何未来收益预测。

## 13. 快速开始

### 方式一：本地服务器（推荐）

```bash
python tools/serve.py                 # 默认 http://127.0.0.1:8321/
python tools/serve.py --port 9000     # 换端口
python tools/serve.py --open          # 自动打开浏览器
```

> **务必用 `tools/serve.py`，不要用 `python -m http.server`。**
> 标准库 `http.server` 是**单线程**的，一次只处理一个请求；浏览器会并发请求 index.html 引用的 12 个 JS 文件，单线程下并发请求被排队甚至超时，表现为部分脚本加载失败、页面卡在"正在加载真实行情数据…"。`tools/serve.py` 使用 `ThreadingHTTPServer`，为每个请求开独立线程。

### 方式二：直接双击 `app/index.html`

无需服务器、无需构建、无需联网。所有资源通过 `<script src>` 同步加载，不含任何 `fetch` / `XHR`，因此不受 `file://` 协议的 CORS 限制。

> 注意：个别浏览器（如某些版本的 Safari）会限制 `file://` 下的 `localStorage`，导致进度无法保存。若遇到"刷新后进度丢失"，改用方式一。

### 方式三：部署到任意静态托管

把 `app/` 目录整体上传至 GitHub Pages / Vercel / 腾讯云 EdgeOne Pages / Nginx 等任意静态托管即可，无需任何构建步骤。注意 `app/data/market-data.js` 为 1.3 MB，建议开启 gzip / brotli 压缩（压缩后约 200 KB 量级）。

### 更新行情数据

```bash
python tools/fetch_market_data.py     # 从东方财富重新抓取，覆盖 data/ 与 app/data/
```

### 运行测试

```bash
node tools/smoke_test.js                                            # 引擎测试，40 项（无需依赖）
npm i jsdom
node tools/render_test.js                                           # 渲染交互测试，54 项
python tools/serve.py &                                             # HTTP 端到端测试需先起服务
node tools/verify_http.js http://127.0.0.1:8321/index.html          # HTTP 端到端，29 项
```
